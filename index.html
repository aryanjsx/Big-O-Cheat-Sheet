Complexity fundamentals and playground

Big O describes how the work an algorithm does grows as the input size n grows. It ignores constants and lower-order terms, so it tells you which algorithm wins on large inputs, not which one is faster on ten items. Change n below to see how the growth classes pull apart.

Logarithms are base 2. In the linear view the chart clips at the top, so the steepest curves leave the plot early. Switch the operations axis to logarithmic to keep every curve in view, or type a larger n to see the table values diverge. Time estimates assume 108 simple operations per second.

O(1): constant

Work does not depend on input size.

def first(items):
    return items[0]

O(log n): logarithmic

Each step discards half of what remains.

def binary_search(items, target):
    lo, hi = 0, len(items) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if items[mid] == target:
            return mid
        if items[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

O(n): linear

One pass over the input.

def total(items):
    result = 0
    for x in items:
        result += x
    return result

O(n log n): linearithmic

Sorting dominates, then one linear pass.

def has_duplicates(items):
    items = sorted(items)
    return any(a == b for a, b in zip(items, items[1:]))

O(n2): quadratic

A loop inside a loop over the same input.

def has_pair_sum(items, target):
    for i in range(len(items)):
        for j in range(i + 1, len(items)):
            if items[i] + items[j] == target:
                return True
    return False

O(2n): exponential

Every item doubles the number of branches.

def count_subsets(items, target, i=0):
    if i == len(items):
        return 1 if target == 0 else 0
    take = count_subsets(items, target - items[i], i + 1)
    skip = count_subsets(items, target, i + 1)
    return take + skip

Average, amortized, and worst case

These three words describe different things, so the tables do not treat them as interchangeable.

Worst case
The most work a single operation can need, on the least favorable input. It holds no matter what the data looks like.
Average (expected) case
The cost averaged over a stated assumption, such as random keys, random insertion order, or a hash function that spreads keys evenly. If the assumption fails, the bound can fail with it.
Amortized case
The cost per operation when you average over a whole sequence of operations, with no randomness involved. An occasional expensive operation (like a resize) is paid for by many cheap ones, but a single operation can still be slow.

Where a bound is tight, it is written with Θ; worst-case columns use O as an upper bound. Implementation details and assumptions behind specific rows are in the notes below.

  1. Stack and queue. Push, pop, enqueue, and dequeue are O(1) when built on a linked list, a circular buffer, or a dynamic array used at one end (a dynamic array's push is amortized O(1)). A queue on a plain array that shifts every element after removing from the front, such as Python's list.pop(0), takes O(n) per dequeue.
  2. Linked lists. Insertion and deletion are O(1) only when you already hold a reference to the position: the head, or the node before it in a singly-linked list. Finding that position takes O(n).
  3. Skip list. Search, insertion, and deletion are expected bounds that come from random level choices; the worst case is O(n). Space is O(n) in expectation; O(n log n) is the worst case when levels are capped at log n.
  4. Hash table. Θ(1) is the expected cost assuming a good hash function that spreads keys evenly and a load factor kept bounded by resizing. If many keys collide, a single operation can take O(n). Insertion is also amortized, because a resize rehashes every key.
  5. Binary search tree. An ordinary BST costs O(h) for search, insertion, and deletion, where h is its height. That is Θ(log n) when the tree is balanced or keys arrive in random order, and O(n) in the worst case, such as inserting sorted keys. Self-balancing trees (AVL, red-black, B-tree) keep h at O(log n) and so give a worst-case guarantee. A BST does not support access by position.
  6. Cartesian tree. The Θ(log n) figures assume random priorities, as in a treap. A tree built from adversarial or already-ordered input can degrade to O(n).
  7. Splay tree. Θ(log n) is an amortized bound over a sequence of operations. A single operation can take O(n), even though the average over many operations is O(log n).
  8. KD tree. The Θ(log n) figures assume points that keep the tree reasonably balanced. Nearest-neighbor search in high dimensions can degrade toward O(n).

A graph has V vertices and E edges. The representation you pick decides which operations are cheap. Here deg(v) is the number of edges at vertex v.

Notation in this table

  • Θ(f) is a tight bound: the cost grows like f and no slower or faster. It is used wherever the bound is known to be tight.
  • O(f) is an upper bound and Ω(f) is a lower bound. They are used where only one side is established.
  • Best, average, and worst name the input, not the bound type. Quicksort, for example, is Θ(n log n) in the best and average cases and Θ(n²) in the worst case.
  • Space is auxiliary space beyond the input array.
  1. Quicksort space. O(log n) when the recursion handles the smaller partition first. A naive implementation can need O(n) stack space in the worst case.
  2. Heapsort. The Θ(n log n) best case holds for distinct keys. Input where every key is equal can finish in O(n).
  3. Bubble sort. The Θ(n) best case needs an early exit when a pass makes no swaps. Without it, every case is Θ(n²).
  4. Tree sort. Assumes inserting into a plain binary search tree, which degrades to Θ(n²) on already-sorted input. A self-balancing tree makes the worst case Θ(n log n).
  5. Shell sort. The running time depends on the gap sequence. Shell's original gaps give O(n²) in the worst case; sequences such as Pratt's give O(n (log n)²). Average-case bounds are not known for most sequences.
  6. Bucket sort. The Θ(n+k) average assumes input spread roughly evenly across buckets. If most items land in one bucket, the cost is dominated by sorting that bucket, up to O(n²).

Graph and tree algorithms

V is the number of vertices, E the number of edges, n the number of tree nodes, and h the tree height (about log n when balanced, up to n when skewed). Graph bounds assume an adjacency list unless noted.

Traversal and search

Algorithm Time Space Notes
Breadth-first search (BFS) O(V + E) O(V) Uses a queue. Finds shortest paths by edge count. O(V2) with an adjacency matrix.
Depth-first search (DFS) O(V + E) O(V) Uses recursion or an explicit stack, so depth can reach V. Basis for cycle detection and topological sort. O(V2) with an adjacency matrix.
Binary search on a sorted array O(log n) O(1) iterative, O(log n) recursive Requires sorted, random-access data. Also works on any monotonic yes/no condition, not just arrays.
Binary search tree lookup O(h) O(1) iterative O(log n) when balanced, O(n) when skewed.
Preorder, inorder, postorder traversal O(n) O(h) Recursion or stack depth is the height. Inorder on a binary search tree visits keys in sorted order.
Level-order traversal O(n) O(w) Uses a queue; w is the widest level, which can be about n/2 in a complete tree.
Morris traversal O(n) O(1) Inorder or preorder with no stack. Temporarily rewires tree pointers, so it is not safe for concurrent readers.

Minimum spanning trees

These algorithms take a connected, undirected, weighted graph. On a disconnected graph they produce a minimum spanning forest.

Algorithm Time Space Notes
Kruskal O(E log E) O(V + E) Sort edges, then add each one that joins two components, using Union-Find. O(E log E) equals O(E log V) because E is at most V2. Works from an edge list.
Prim with binary heap O(E log V) O(V + E) Grows one tree from a start vertex. Good for sparse graphs.
Prim with array O(V2) O(V) Good for dense graphs stored as a matrix.
Prim with Fibonacci heap O(E + V log V) O(V + E) Best bound, rarely fastest in practice.
Borůvka O(E log V) O(V) Each round adds the cheapest edge leaving every component. Components at least halve each round, so it needs at most log V rounds. Easy to parallelize.

Coding patterns

Interview problems tend to reuse a handful of patterns. Knowing the typical cost of each lets you estimate a solution before you write it.

These are typical complexities, not guarantees. The real cost depends on the problem, on how you implement the pattern, and on any extra work such as sorting the input first. Always check the bound against your own code.

Coding pattern Typical time complexity Typical auxiliary space Typical problems and caveats
Two pointers O(n) O(1) Pair sum on a sorted array, removing duplicates in place, palindrome check. If the input is not sorted and the pattern needs it, add O(n log n) for the sort.
Sliding window O(n) O(1) or O(n) Longest substring or subarray under a constraint. Space is O(1) for a running sum or count, and grows when the window stores its contents, such as a character map or a deque for the window maximum.
Prefix sums O(n) preprocessing; O(1) per range sum O(n) Many range-sum queries on a fixed array. Updates to the array force a rebuild, or a Fenwick or segment tree instead.
Hash map frequency counting Expected O(n) total O(n) Anagrams, duplicates, two-sum. Relies on expected O(1) hash operations; heavy collisions can make a single operation O(n).
Monotonic stack O(n) total O(n) Next greater element, daily temperatures, largest rectangle in a histogram. Each item is pushed and popped at most once.
Backtracking and subsets O(2n) output generation Depends on implementation Recursion depth alone is O(n). Storing every subset needs O(n·2n) space, and copying each subset into the result adds a factor of n to the time.
Permutations O(n·n!) to generate all permutations Depends on output and implementation There are n! permutations of length n. Recursion depth is O(n); storing all of them takes O(n·n!).
Dynamic programming Number of states × transitions per state Depends on memoization or tabulation Knapsack with n items and capacity W has n·W states with two transitions each, so O(n·W) time. Tabulation often lets you keep only the previous row, cutting space to O(W). Memoization also uses recursion stack space.

Reading the notation

  • O(...) describes an asymptotic upper bound.
  • Ω(...) describes an asymptotic lower bound.
  • Θ(...) describes a tight asymptotic bound.
  • n is the input size. Graph algorithms use V for vertices and E for edges. Some algorithms use extra parameters, such as k or m, as noted in each table.
  • α(n) is the inverse Ackermann function. It grows so slowly that it is at most 4 for any practical input.
  • Average (expected) cost depends on a stated assumption, such as random input or a well-behaved hash function. Amortized cost is the average per operation over a worst-case sequence of operations and involves no randomness. Worst-case cost is the most a single operation can take. See the notes under the data structure table.
  • Tables use Θ where a bound is known to be tight, O for upper bounds, and Ω for lower bounds.
  • N/A means the operation is not applicable in that table's context.

Complexities are quick-reference summaries. Actual performance depends on the implementation, the input, and the assumptions behind each operation, so check the linked references when exact guarantees matter.
